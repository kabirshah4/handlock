# Design: Enforced file locks for multi-agent coding

Generated by /office-hours on 2026-11-18
Mode: Builder (open source)
Status: DRAFT
Working name: TBD (pick before first publish)

## Problem Statement

People now run several coding agents at once (Claude Code, Codex, Copilot, OpenCode) in the same repo. Nothing stops two of them editing the same file. Today's fix is a polite rule in a notes file ("check open handoffs before editing"), which agents follow only when they remember to.

## What Makes This Cool

**The handoff note is the lock.** An open handoff's "Files you own" list is the lock itself: no separate lock store to drift out of sync. Every agent's own edit hook checks it and refuses edits to files another agent owns, pointing to the handoff that owns them. Git pre-commit catches anything that slips past.

Demo (first screen of the README): Codex tries to edit a file Claude owns, gets blocked live, and is told which handoff to read.

## Constraints

- Notes stay plain markdown with YAML frontmatter. They must work unchanged in an Obsidian vault.
- No daemon, no server, no account. Works in any folder.
- Enforcement must be real where the agent's hook API allows blocking. Where it doesn't, fall back to pre-commit and say so plainly in the README.
- No secrets in handoff notes (carry over the vault rule).

## Premises (agreed)

1. Lead with "your agents can't step on each other", not "another handoff spec". The format is just how the locks are stored.
2. Enforcement lives in each agent's own edit hooks plus a git pre-commit backstop. Advisory-only would be one more aisync.
3. Notes stay plain markdown, Obsidian-compatible, so the open handoff is the lock.
4. v1 doesn't launch without a one-command install and the "agent gets blocked" demo GIF.

## Landscape (searched 2026-11-18)

- **Handoff specs are crowded, none standard:** ai-handoff-md, OpenMOSS/claude-codex-handoff, agent-handoff-kit, llm-handoff, HaoPan036/agent-handoff, your-turn-loop, agent-handoff-protocol, codex-cc-handoff.
- **Locks exist only as advisory:** aisync (CLI claims, exit code 3), Vibsync (MCP check-then-claim), and blog posts on lease-based locks. None enforces inside each agent's own hooks.
- **Takeaway:** don't compete on the spec. Compete on enforcement, with the spec as a byproduct.

## Approaches Considered

### A: Minimal
CLI + Claude Code edit hook + git pre-commit only. Human ~2 days / CC ~1 hr. Other agents caught only at commit, so the demo is weaker.

### B: Full adapters (CHOSEN)
Shared lock resolver + per-agent hook adapters + pre-commit + one-command init. Human ~1-2 weeks / CC ~half a day.

### C: Worktree per handoff
A worktree per receiving agent with a merge gate on "Files you own". No hook work, but worktrees bring their own failures (shared lock files, conflicts at merge time).

## Recommended Approach: B

### Handoff format (v1)

```markdown
---
type: handoff
from: Claude
to: Codex
project: cohesive-ui
status: open        # open | in_progress | done | cancelled
created: 2026-11-18
---
# Task title

## Context
## Files you own
- `skills/cohesive-ui/scripts/extract-design.js`
- `tests/fixtures/**`
## Don't touch
- everything else
## Done when
- [ ] ...
## Result
```

Taken directly from the existing AI Team `Handoff Template.md`, so the vault is user #1 with zero migration.

### Lock rules

- A handoff with `status` open or in_progress grants `to` exclusive write on each path or glob in "Files you own".
- An edit to an owned path by any agent other than the owner is blocked, with a message: owner, handoff file, how to release.
- "Don't touch" adds explicit denies for the receiving agent itself.
- Unowned files stay free (opt-in locking, so it never gets in the way of a repo that doesn't use it).
- Two open handoffs claiming the same path is an error raised at `handoff new` / `claim` time.
- `done` or `cancelled` releases the locks. Stale locks: `handoff release <file>` and a `--force` override that's logged in the note.

### Components

1. **core**: parses handoff notes and answers `canEdit(agent, path)`. One implementation; every hook calls it.
2. **CLI**: `init`, `new`, `claim`, `done`, `release`, `list`, `check <agent> <path>`.
3. **Adapters**, one per agent, each a thin shim calling `check`:
   - Claude Code: PreToolUse hook on Edit/Write/MultiEdit (blocking supported).
   - Codex, OpenCode, Copilot: wire into each one's pre-tool hook or plugin mechanism. **Verify each can actually block a file write before claiming support.** If one can't, it's listed as "pre-commit only".
4. **git pre-commit**: rejects staged changes to paths owned by someone other than the committing agent (agent identified by env var set by each adapter, falling back to a commit trailer).
5. **`npx <name> init`**: detects installed agents, installs their adapters and the pre-commit hook, creates `handoffs/` (or points at an existing folder such as an Obsidian vault).

### Agent identity

Each adapter sets/reads its own agent name, so the core knows who is asking. Unknown agent = treated as a human: warned, not blocked (humans stay in charge).

## Open Questions

- Which language for core/CLI: Node (npx install, matches the demo) or Python. Leaning Node.
- Exact blocking ability of the Codex, OpenCode and Copilot hook APIs (verify first; it decides the support table).
- Handoff folder location default: `./handoffs/` in the repo vs an external vault path. Support both via config.
- Project name.

## Success Criteria

- The demo GIF works end to end in at least Claude Code plus one other agent, with pre-commit catching the rest.
- `npx <name> init` to first blocked edit in under 60 seconds on a fresh repo.
- Your own AI Team vault runs on it for a week with no manual lock-keeping.
